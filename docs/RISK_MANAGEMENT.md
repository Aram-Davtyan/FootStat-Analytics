# Идентификация, анализ и картографирование рисков ИС

## 1. Цель работы
Идентифицировать, проанализировать и картографировать рисковые факторы на стадиях жизненного цикла ИС,
а также определить превентивные мероприятия для нормализации рискового фона и устойчивости процесса.

## 2. Объект исследования (в рамках проекта)
ИС предоставляет поиск и отображение профиля игрока, используя внешний источник Sofascore.
Критические зависимости: доступность API, корректность данных, безопасность ключей доступа,
стабильность фронтенда.

## 3. Стадии жизненного цикла ИС
- Анализ требований
- Проектирование
- Разработка
- Тестирование
- Внедрение
- Эксплуатация и сопровождение

## 4. Классификация рисков
- Организационные (сроки, ресурсы, компетенции).
- Технические (интеграции, производительность, безопасность).
- Качественные (дефекты, регрессии).
- Эксплуатационные (доступность, мониторинг, обновления).
- Правовые/лицензионные (условия API, ключи доступа).

## 5. Методика оценки
### 5.1. Шкалы
- Вероятность: Н (низкая), С (средняя), В (высокая).
- Влияние: Н (низкое), С (среднее), В (высокое).

Оценка:
- Н/Н: низкий риск
- С/С: средний риск
- В/В: высокий риск

## 6. Реестр рисков по стадиям
### 6.1. Анализ требований
- R1: Неполные/неясные требования.
  - Вероятность/влияние: С/С.
  - Триггеры: частые изменения формулировок, противоречия.
  - Превентивные меры: фиксация требований в документации, критерии готовности.

- R2: Недооценка ограничений внешнего API (лимиты, блокировки).
  - Вероятность/влияние: С/В.
  - Триггеры: 429/403 от API, рост количества запросов.
  - Превентивные меры: анализ SLA, тест ключевых эндпоинтов, проект фолбэков.

### 6.2. Проектирование
- R3: Неверное разделение ответственности модулей.
  - Вероятность/влияние: С/С.
  - Триггеры: смешение логики в контроллерах, сложность изменений.
  - Превентивные меры: схема MVC, ревью сервиса и репозитория.

- R4: Отсутствие плана обработки ошибок API.
  - Вероятность/влияние: В/С.
  - Триггеры: необработанные исключения, пустые страницы.
  - Превентивные меры: единый слой ошибок, таймауты, retry/backoff.

### 6.3. Разработка
- R5: Нестабильность внешнего API (403/ограничения).
  - Вероятность/влияние: В/В.
  - Триггеры: ошибки в логах, жалобы на отсутствие данных.
  - Превентивные меры: серверный прокси, graceful fallback, кэширование.

- R6: Утечка ключей API.
  - Вероятность/влияние: С/В.
  - Триггеры: ключи в репозитории, ошибки CI на секреты.
  - Превентивные меры: хранение в ENV, исключение из Git, ревизия настроек.

### 6.4. Тестирование
- R7: Недостаток тестового покрытия.
  - Вероятность/влияние: С/С.
  - Триггеры: повторяющиеся регрессии, ручное тестирование всего.
  - Превентивные меры: smoke-чек-лист, минимальные автотесты.

- R8: Тесты зависят от внешнего API.
  - Вероятность/влияние: С/С.
  - Триггеры: флапающие тесты, нестабильные ответы.
  - Превентивные меры: мокирование ответов, изоляция интеграционных тестов.

### 6.5. Внедрение
- R9: Несовместимость конфигураций окружений.
  - Вероятность/влияние: С/В.
  - Триггеры: различия в `.env`, неожиданные 5xx на проде.
  - Превентивные меры: шаблоны конфигов, checklist релиза.

- R10: Отсутствие плана отката.
  - Вероятность/влияние: С/В.
  - Триггеры: падение после релиза, отсутствует стабильный тег.
  - Превентивные меры: теги версий, инструкции rollback, резервные копии.

### 6.6. Эксплуатация и сопровождение
- R11: Деградация производительности при пиковых запросах.
  - Вероятность/влияние: С/С.
  - Триггеры: рост времени ответа, таймауты.
  - Превентивные меры: кэширование, лимиты, мониторинг.

- R12: Изменение формата ответов API.
  - Вероятность/влияние: С/В.
  - Триггеры: новые поля/структуры, ошибки парсинга.
  - Превентивные меры: валидация данных, логирование, обновление DTO.

## 7. Картографирование рисков (ASCII)
```
Влияние
  В | R2  R5  R6  R10  R12
  С | R1  R3  R4  R7  R8  R9  R11
  Н | 
     Н   С   В  Вероятность

R1: требования неясны
R2: ограничения API
R3: архитектурные ошибки
R4: ошибки обработки API
R5: нестабильность API
R6: утечка ключей
R7: недостаток тестов
R8: зависимость тестов от API
R9: несовместимость окружений
R10: отсутствие отката
R11: деградация производительности
R12: изменения формата API
```

## 8. Превентивные мероприятия
### 8.1. Процессные меры
- Регламенты: фиксация требований и критериев готовности.
- Ревью: обязательное для изменений API и логики.
- Release checklist: конфиги, миграции, тесты, документация.

### 8.2. Технические меры
- Обработка ошибок: единый слой ошибок и таймауты в репозитории.
- Надежность: прокси изображений, фолбэки, кэширование.
- Безопасность: хранение ключей в ENV, проверка секретов.

### 8.3. Эксплуатационные меры
- Мониторинг: метрики ошибок API, время ответа.
- Логи: централизованный сбор ошибок по ключевым сценариям.
- План отката: теги релизов, инструкция rollback.

## 9. Контрольные точки (KPI рисков)
- Доля успешных запросов к API > 98%.
- Среднее время ответа API < 1.5 сек.
- Доля регрессий на релиз < 5%.
- Доля окружений с корректной конфигурацией = 100%.

## 10. Итог
Основные риски связаны с внешним API, стабильностью конфигураций и качеством тестирования.
Сформирован реестр рисков по стадиям, определены триггеры и превентивные меры,
что нормализует рисковый фон процесса информатизации и обеспечивает устойчивость ИС.
